# OptoGPT 第三版：生成、搜索与 TMM 筛选

第三版使用原 checkpoint，不重新训练。改变的是如何从模型的下一层概率分布中搜索结构，以及如何筛选结果。提高搜索预算有机会改善光谱，但较低 top-k/top-p/温度也可能错过低概率的好结构，不能保证所有目标都有改善。

## 参数含义与默认值

模型每一步预测一个 token，例如 `SiO2_100` 表示材料 SiO2、厚度 100 nm；也可以输出 EOS 表示结束。概率来自目标 R/T 光谱和已经生成的各层。

| 设置 | v3 默认 | 具体作用 |
| --- | --- | --- |
| Top-k | 10 | 每一步最多保留概率最高的 10 个 token，包括可能的 EOS。不是 10 种材料或 10 个膜系。 |
| Top-p | 0.85 | 按温度调整后的概率降序取 token，直到累计概率达到 85%，同时受 top-k 上限约束。包含跨过阈值的 token，再重新归一化抽样。top-k 限制可能使累计概率达不到 p。 |
| 温度 | 0.7、0.85、1.0 | 通过 softmax(log-probability / temperature) 调整分布。小于 1 更集中；1 保留原来的相对概率。三档分别运行，不是将光谱或概率平均。 |
| 起始种子 / 种子数 | 42 / 4 | 默认使用 42、43、44、45；每个种子与每档温度有独立 RNG。固定参数、checkpoint 和同一计算环境可重复搜索；不同硬件不保证位级一致。 |
| 随机抽样次数 | 300 | 一共 300 次完整序列抽样，在 4×3=12 个组合间轮转分配，每组 25 次。不是每组 300 次。重复结构仍消耗预算；UI 可选 200–500。 |
| 最终保留数量 | 20 | 完成全部搜索后去重、逐组 TMM 验证，再返回误差最小的最多 20 组。如果唯一结果不足，不伪造或重复补齐。 |
| 最大层数 | 20 | EOS 可以提前结束；达到上限时返回当前结构前缀。这是硬上限，不是强制生成 20 层，也不是严格的有层数约束条件分布。 |
| Greedy | 开启 | 每步取当前概率最大的 token，得到一条确定性路径；可能与其他候选重复。 |
| Beam 宽度 | 5 | 每步扩展并保留得分最好的最多 5 条路径；0 关闭。它根据模型序列概率搜索，最终仍须 TMM 判断光谱。 |
| 长度归一化 α | 0.6 | beam 得分 = 累积 log 概率 / ((5+L)/6)^α，取高分。α=0 不归一化；α>0 减轻累积负 log 概率对长序列的偏向。它不是制造复杂度惩罚。 |

L 不包括 BOS；实际输出 EOS 时计入一次长度。结束的 beam 原样保留，不在 EOS 后继续生成。达到层数上限时不虚构 EOS 概率。BOS/PAD/UNK 不允许作为膜层，第一步屏蔽 EOS，避免空结构。

Top-p 的累计概率使用温度调整、特殊 token 屏蔽后的完整分布，**不先把 top-k 子集归一化**。这与仓库上游联合 top-k/top-p 循环的含义一致。例如概率 0.4、0.3、0.2、0.1，k=3、p=0.8 时保留前三个，再归一化为 4/9、3/9、2/9。

默认最多产生 300 个随机输出 + 1 个 greedy 输出 + 5 个 beam 输出。按完整材料/厚度 token 序列去重，合并来源记录，然后每个唯一结构进行一次 TMM 验证。抽样阶段的计数代表尝试预算，验证阶段的计数代表唯一结构数。

这里的“上游已有”指源代码中的推理解码或分析脚本，并不意味着它们存储在 checkpoint 内。

| 功能 | 上游 / 旧工作台 / 第三版 |
| --- | --- |
| 目标光谱条件生成、材料厚度 token、EOS | OptoGPT 模型本身；旧版已有。 |
| top-k 随机采样 | 上游和旧版已有；第三版将 UI 暴露并把默认 50 改为 10。 |

| beam search | 上游 `self_improving/prepare_aug_data.py` 已有普通 beam；第三版重新实现，增加长度归一化、正确冻结 EOS、token 屏蔽和取消检查。 |
| 多次生成、TMM 选优 | 上游已有该思路，`TOP-KP Decode_v2` 已执行多次解码后选优；旧工作台仅取到指定唯一数量后停止。第三版分开“抽样预算”和“保留数量”。 |
| 温度与随机种子 | 旧工作台已有单温度和单种子；第三版新增多温度×多种子轮转调度、独立 RNG。 |

| 200–500 次、4–8 种子、三档温度、α=0.6 | 本项目选择的初始配置，不是论文对所有任务证明的最优值。 |

上游参考：<https://github.com/taigaoma1997/optogpt>。本仓库保留其快照于 `third_party/optogpt/`，这次未修改上游文件。

## 最终筛选与兼容性

第三版按 `(wR × MAE_R + wT × MAE_T)/(wR+wT)` 排名，UI 默认为 R/T 等权。只有光谱误差相同时，才用原综合分（含层数和厚度惩罚）打破平局。原 `score` 字段保留以兼容历史项目，比较页明确标注其为复杂度综合参考分。

返回 `search_summary`、实际 `search_settings`、目标快照与候选来源。逆向页可导出整个搜索 JSON，完整记录可复现参数；已有项目 JSON 和旧任务仍可读取。v2 会话的单温度配置迁移到 v3 三档默认值，其他已有基础设置保留；新设置在同标签页刷新后恢复。后端任务仍驻留内存，重启后不能续算。

旧 API 的 `temperature` 仍可用：若未传 `temperatures`，显式 `temperature` 被当作单档，否则采用 v3 三档默认。`candidate_count` 现在只控制最终保留数量，计算预算由 `sample_count` 决定。API 允许更小预算用于测试，但预算至少覆盖每一个种子/温度组合。

这次不包括连续厚度优化、材料约束、微调、不同角度/基底反演或细波长网格。TMM 条件保持 400–1100 nm、10 nm 间隔、法向 s 偏振、500 μm 非相干玻璃基底和空气入射/出射。

## 运行与验证

在 frontend 运行 `npm run build`，然后重启后端。模型可通过 `OPTOGPT_MODEL_PATH` 指向已有 checkpoint，不需要复制到 Git。

使用 OptoGPT Python 环境运行：

```powershell
python -m unittest discover -s tests -v
python -m scripts.benchmark_search --samples 300 --targets bandpass anti-reflection
```

基准使用真实 checkpoint 和 TMM，与保留的 v2 CLI 采样算法比较，打印光谱 MAE、样本数量和时间。更多候选通常需要更长计算时间。单次种子和少数模板只能做有限验证，不能推导全部目标的平均提升。

### 本次实测（2026-09-22）

PyTorch 2.0.1、CUDA 11.8、RTX 2050；seed=42，v3 使用上述默认参数。时间为模型加载后生成与 TMM 验证的总时间，未包含首次加载。指标为最佳候选的 (MAE_R+MAE_T)/2，百分数表示光谱绝对误差乘 100。

| 目标 | v2 最佳 MAE | v3 最佳 MAE | v2 / v3 时间 | v3 唯一 / 保留 |
| --- | --- | --- | --- | --- |
| 内置带通（540–680 nm） | 19.6050% | 18.3927% | 17.47 / 129.32 s | 219 / 20 |
| 内置宽带增透 | 3.7606% | 3.8264% | 4.56 / 38.77 s | 11 / 11 |

带通误差相对降低约 6.18%，但绝对误差仍较高；增透略有变差，并有 295/306 个重复输出。这说明集中采样可能损失多样性，默认值不是通用最优解。对重复率很高的目标可以在 UI 增大 top-k、top-p 或温度后对照验证；只增加相同分布的抽样次数并不一定有效。当前版本忠实实现推荐搜索流程，不把上述结果解释为已解决全部精度瓶颈。

自动测试 15 项通过，包含联合过滤、温度概率、EOS 冻结、长度归一化、跨种子复现、取消和全部验证后选优；前端 TypeScript 检查和生产构建通过。浏览器检查确认了新增控件与刷新后的参数恢复，并实际提交宽带增透任务，确认 300 次抽样、306 个输出、11 个唯一验证结果及来源/误差展示与离线基准一致。
